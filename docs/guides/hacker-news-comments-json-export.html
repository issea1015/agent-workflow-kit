Download Hacker News comments as JSON

Hacker News has a free, official search API with no key. Here is how to pull comments and whole threads as JSON, and how to set up simple monitoring for mentions of your product.

1. Search comments and stories

Hacker News has an official public search API powered by Algolia. No key, no login. Two endpoints:

  • https://hn.algolia.com/api/v1/search?query=...: sorted by relevance (then points and comment count).
  • https://hn.algolia.com/api/v1/search_by_date?query=...: newest first. Use this one for monitoring.

Useful parameters:

  • tags=comment, tags=story, tags=show_hn, tags=ask_hn. Comma means AND, e.g. tags=story,show_hn; parentheses mean OR, e.g. tags=(story,comment). tags=story_8863 limits results to one thread, tags=author_pg to one user.
  • numericFilters: filter on created_at_i (Unix seconds), points and num_comments, e.g. numericFilters=created_at_i>1731000000,points>=10.
  • hitsPerPage (up to 1000) and page (0-based). A query returns at most about 1000 hits in total, so narrow the time window instead of paging deeper.
  • restrictSearchableAttributes=url finds stories linking to a domain: query=example.com&restrictSearchableAttributes=url.
https://hn.algolia.com/api/v1/search_by_date?query=claude%20code&tags=comment&numericFilters=created_at_i%3E1731000000&hitsPerPage=100

Each hit has objectID, author, created_at, created_at_i, story_id, story_title, parent_id and comment_text (HTML) for comments; stories have title, url, points and num_comments. The discussion link for any id is https://news.ycombinator.com/item?id=<objectID>. Search is full-text, so quote an exact phrase, and expect results to lag a few minutes behind the live site.

2. Get a full comment tree

Search returns comments one by one. To get a whole thread as a nested tree, use the items endpoint:

https://hn.algolia.com/api/v1/items/8863

The response is the story with a children array; each child is a comment with its own children, plus author, text, created_at and parent_id. Walk it recursively to flatten it with a depth.

3. A working Python script (standard library only)

import html, json, re, urllib.parse, urllib.request

def get(url):
    with urllib.request.urlopen(url, timeout=30) as r:
        return json.load(r)

def strip(s):
    s = re.sub(r"<p>", "\n\n", s or "")
    return html.unescape(re.sub(r"<[^>]+>", "", s))

def flatten(node, depth=0, out=None):
    out = [] if out is None else out
    for c in node.get("children", []):
        if c.get("text"):                       # deleted comments have no text
            out.append({"id": c["id"], "parent": c["parent_id"], "depth": depth,
                        "author": c["author"], "date": c["created_at"],
                        "text": strip(c["text"])})
        flatten(c, depth + 1, out)              # replies of deleted comments are kept
    return out

# one thread, flattened
comments = flatten(get("https://hn.algolia.com/api/v1/items/8863"))
print(len(comments), "comments")

# search: newest comments mentioning a phrase
q = urllib.parse.urlencode({"query": '"claude code"', "tags": "comment", "hitsPerPage": 50})
for h in get("https://hn.algolia.com/api/v1/search_by_date?" + q)["hits"]:
    print(h["created_at"], h["author"], "https://news.ycombinator.com/item?id=" + h["objectID"])

The text fields are HTML (<p>, <a>, <i>, entities), which is why the script strips tags and unescapes entities.

4. A mention-monitoring recipe

  1. List the strings that mean you: your product name, your domain, your handle, key competitors. Use quoted phrases for names that are common words.
  2. Once an hour or day, call search_by_date twice per string: once with tags=comment, once with tags=story. Set numericFilters=created_at_i>LAST_RUN, where LAST_RUN is the Unix time of your previous run.
  3. Store seen objectIDs so a retry never reports the same hit twice.
  4. For each new story that matters, fetch the full tree with the items endpoint and see who replied and how.
  5. Send new hits to Slack, email or a file. A cron job is enough.
  6. Check for false positives: a short brand word will match unrelated threads. Filter by points or require a second word.

For stories that link to your site, search the domain with restrictSearchableAttributes=url and tags=story: it shows who posted you, with points and comment counts.
