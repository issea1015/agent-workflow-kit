How to stop Claude Code from running rm -rf and other destructive commands

Approving every command gets old fast, and auto-accept means one bad guess can delete a folder or overwrite main. A PreToolUse hook gives you a safety net: it checks each shell command before it runs and blocks the catastrophic ones.

How a blocking hook works

Claude Code runs PreToolUse hooks before every tool call and sends them the call as JSON on stdin. If the hook exits with code 2, the call is blocked and whatever the hook printed to stderr goes back to Claude, so it can change its approach. Exit code 0 lets the call through.

1. Install a free guard hook (1 minute)

guard-dangerous-bash is about 50 lines of standard-library Python. It makes no network calls and writes no files. Read it first, then:

mkdir -p ~/.claude/hooks
curl -o ~/.claude/hooks/guard-dangerous-bash.py \
  https://raw.githubusercontent.com/issea1015/guard-dangerous-bash/main/guard.py

Register it in ~/.claude/settings.json so it applies to every project:

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "python3 ~/.claude/hooks/guard-dangerous-bash.py" }] }
    ]
  }
}

2. Test it without running anything dangerous

The hook only reads JSON, so you can feed it a fake tool call. Nothing gets executed:

echo '{"tool_name":"Bash","tool_input":{"command":"rm -rf ~"}}' \
  | python3 ~/.claude/hooks/guard-dangerous-bash.py; echo "exit=$?"
Blocked by guard-dangerous-bash: recursive delete of the root or home directory. If this is really intended, run it yourself outside Claude Code.
exit=2

Normal work passes through: rm -rf ./build and git push origin feature both exit 0.

What it blocks

  • rm -rf /, rm -rf ~, rm -rf $HOME, including at the end of a chain like cd /tmp && rm -rf /
  • force pushes to main or master
  • curl … | sh and wget … | bash (running a downloaded script)
  • mkfs, dd of=/dev/sdX, redirects onto disk devices, fork bombs, chmod -R 777 /

What it doesn't do

It's a safety net, not a sandbox. It matches command text, so a determined script can get around it, and it only watches the Bash tool. Keep using version control, and run untrusted projects in a container. Permission deny rules in settings.json are a good complement: they match how a command starts, while a hook sees the whole command string.

Also check the hooks you already have. A hook runs with your permissions, and skills or plugins can add them. How to audit Claude Code hooks shows a 10-second check.
