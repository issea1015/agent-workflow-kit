Claude Code permissions: a safe allow list (and rules never to add)

Every "Yes, don't ask again" adds a rule to your settings. A few months later the allow list is long, and one or two of those rules let the agent run anything. Here's what a sane list looks like, and how to check yours.

Where the rules live

Permission rules sit under "permissions" in ~/.claude/settings.json, .claude/settings.json and .claude/settings.local.json, in three lists: allow (runs without asking), ask and deny. Deny wins over allow. Type /permissions inside Claude Code to see what's in effect.

A safe starting point

{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Bash(npm run lint:*)",
      "Bash(git status)",
      "Bash(git diff:*)",
      "WebFetch(domain:docs.python.org)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ]
  }
}

Allow the specific commands you run all day (tests, lint, read-only git). Deny reads of files that hold secrets, so they never land in the agent's context.

Rules never to add

  • Bash or Bash(*): every shell command runs without asking.
  • Bash(rm:*), Bash(sudo:*), Bash(dd:*): deletion, root, raw disk writes.
  • Bash(curl:*), Bash(wget:*): the agent can download code or send your files anywhere.
  • Bash(bash:*), Bash(python3:*), Bash(npx:*): "run this script" is the same as "run anything".
  • Bash(git push:*): publishing should be a human decision.
  • "defaultMode": "bypassPermissions": no prompts at all. Only for throwaway containers.

Check your settings in one command (free)

permission_check.py is a free, read-only script. With no arguments it reads every settings file Claude Code uses and flags the rules above:

$ python3 permission_check.py .claude/settings.json
HIGH   .claude/settings.json permissions.allow 'Bash(rm:*)': pre-approves `rm`: deletes files
MEDIUM .claude/settings.json permissions.allow 'Bash(git push:*)': pre-approves `git push`: publishes code
MEDIUM .claude/settings.json permissions.allow 'WebFetch': allows fetching any URL; prefer WebFetch(domain:example.com)
LOW    all files: no deny rule for .env; consider "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"]
checked 1 file(s): FAIL (1 high, 3 other)

A rule list isn't a safety net

Prefix rules match what a command starts with, so a chained command can still surprise you. A PreToolUse hook sees the full command before it runs: block rm -rf, force-push and curl | sh with a free hook.
