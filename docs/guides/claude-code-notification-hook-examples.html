Claude Code Notification hook examples: 5 copy-paste hooks (tested)

A Notification hook runs when Claude Code sends a notification, such as waiting for your approval or sitting idle. It is the place for desktop alerts, sounds, logs and webhooks. Five small hooks, each tested by piping in the JSON Claude Code sends.

How a Notification hook works

The Notification event fires when Claude Code sends a notification, for example when it is waiting for you to approve a tool use or has been idle. Besides the common fields (session_id, transcript_path, cwd, hook_event_name), the JSON on stdin has message (the notification text), an optional title, and notification_type saying which type fired:

{"session_id": "abc123", "cwd": "/Users/...", "hook_event_name": "Notification",
 "message": "Claude needs your permission", "title": "Permission needed",
 "notification_type": "permission_prompt"}

The matcher is matched against notification_type; leave it out to run for every type. The two types you will use most:

  • permission_prompt: Claude needs you to approve a tool use, and the prompt has waited about six seconds
  • idle_prompt: Claude finished responding about 60 seconds ago and you have not typed since

There are other types too (such as auth_success and elicitation_dialog); see the hooks reference for the full list. Notification hooks cannot block or modify a notification, and exit code 2 is ignored, so they are for side effects only. Claude Code also discards their systemMessage and continue output but still emits a terminalSequence field, which examples 2 and 4 use. That field only works in interactive sessions, not with -p or the Agent SDK. Register scripts in .claude/settings.json; each example shows its entry.

Check the current hooks reference for details; this guide only uses the fields listed above.

1. Desktop notification (macOS and Linux)

Pops a native notification with the message and title. Uses osascript on macOS and notify-send on Linux; does nothing if neither is available. Arguments are passed as separate arguments, never spliced into a shell string, so odd characters in the message cannot break the command.

import json, platform, shutil, subprocess, sys
data = json.load(sys.stdin)
title = data.get("title") or "Claude Code"
message = data.get("message") or "Needs your attention"
if platform.system() == "Darwin":
    script = 'display notification (item 2 of argv) with title (item 1 of argv)'
    cmd = ["osascript", "-e", "on run argv", "-e", script, "-e", "end run", title, message]
elif shutil.which("notify-send"):
    cmd = ["notify-send", title, message]
else:
    sys.exit(0)  # no notifier installed: do nothing
subprocess.run(cmd, check=False)
sys.exit(0)
{
  "hooks": {
    "Notification": [
      {"hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/desktop_notify.py"}
      ]}
    ]
  }
}
$ echo '{"session_id":"s1","cwd":"$PWD","hook_event_name":"Notification","message":"Claude needs your permission to use Bash","title":"Permission needed","notification_type":"permission_prompt"}' | python3 desktop_notify.py; echo "exit=$?"
exit=0
$ cat stub.out   # notify-send was a stub script on PATH that records its arguments
notify-send args: Permission needed Claude needs your permission to use Bash

Tested with a stub notify-send, so the script logic is verified; the real popup depends on your desktop.

2. Terminal bell

The simplest alert: ask the terminal to ring its bell, using the terminalSequence output field. Many terminals turn the bell into a sound, a tab badge or a dock bounce.

import json, sys
json.load(sys.stdin)
print(json.dumps({"terminalSequence": "\a"}))
sys.exit(0)
{
  "hooks": {
    "Notification": [
      {"hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/bell.py"}
      ]}
    ]
  }
}
$ echo '{"session_id":"s1","cwd":"$PWD","hook_event_name":"Notification","message":"Claude needs your permission to use Bash","title":"Permission needed","notification_type":"permission_prompt"}' | python3 bell.py; echo "exit=$?"
{"terminalSequence": "\u0007"}
exit=0

3. Log every notification to a file

Keeps a tab-separated history of what Claude asked for and when, in .claude/notifications.log. Handy for finding out how often a session sat waiting on you. Remember to git-ignore the file.

import datetime, json, os, sys
data = json.load(sys.stdin)
cwd = data.get("cwd") or "."
path = os.path.join(cwd, ".claude", "notifications.log")
os.makedirs(os.path.dirname(path), exist_ok=True)
stamp = datetime.datetime.now().astimezone().strftime("%Y-%m-%d %H:%M:%S")
line = f'{stamp}\t{data.get("notification_type", "?")}\t{data.get("message", "")}'
with open(path, "a", encoding="utf-8") as f:
    f.write(line.replace("\n", " ") + "\n")
sys.exit(0)
{
  "hooks": {
    "Notification": [
      {"hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/log_notification.py"}
      ]}
    ]
  }
}
$ echo '{"session_id":"s1","cwd":"$PWD","hook_event_name":"Notification","message":"Claude needs your permission to use Bash","title":"Permission needed","notification_type":"permission_prompt"}' | python3 log_notification.py; echo "exit=$?"
exit=0
$ cat .claude/notifications.log
2026-11-14 19:16:57	permission_prompt	Claude needs your permission to use Bash
2026-11-14 19:16:57	idle_prompt	Claude is waiting for your input

4. Only alert on permission and idle prompts

Set the matcher to permission_prompt|idle_prompt so the hook only runs for those two types. The script checks the type again, so it stays safe if you later widen the matcher, and it sends a different text for each. It uses the OSC 777 desktop-notification escape sequence through terminalSequence, the same approach as the example in the official docs; whether your terminal shows it depends on the terminal.

import json, sys
data = json.load(sys.stdin)
kind = data.get("notification_type")
if kind == "permission_prompt":
    text = "Approval needed: " + data.get("message", "")
elif kind == "idle_prompt":
    text = "Claude is waiting for your next prompt"
else:
    sys.exit(0)  # ignore every other type
print(json.dumps({"terminalSequence": f"\033]777;notify;Claude Code;{text}\a"}))
sys.exit(0)
{
  "hooks": {
    "Notification": [
      {"matcher": "permission_prompt|idle_prompt", "hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/filter_notify.py"}
      ]}
    ]
  }
}
$ echo '{"message":"Claude needs your permission to use Bash","notification_type":"permission_prompt"}' | python3 filter_notify.py; echo "exit=$?"
{"terminalSequence": "\u001b]777;notify;Claude Code;Approval needed: Claude needs your permission to use Bash\u0007"}
exit=0
$ echo '{"notification_type":"idle_prompt"}' | python3 filter_notify.py
{"terminalSequence": "\u001b]777;notify;Claude Code;Claude is waiting for your next prompt\u0007"}
$ echo '{"notification_type":"auth_success"}' | python3 filter_notify.py; echo "exit=$?"   # ignored
exit=0

5. Forward to a webhook (URL from an env var)

Posts a small JSON body to whatever URL is in CLAUDE_NOTIFY_WEBHOOK, for a chat bot, a phone push relay or your own endpoint. The URL stays out of your repo. If the variable is unset the hook does nothing, and a network failure is reported on stderr but never fails the session. Use a URL you control and keep it secret.

import json, os, sys, urllib.request
data = json.load(sys.stdin)
url = os.environ.get("CLAUDE_NOTIFY_WEBHOOK")
if not url:
    sys.exit(0)  # not configured: do nothing
body = json.dumps({
    "text": data.get("message", ""),
    "type": data.get("notification_type", ""),
    "project": os.path.basename(data.get("cwd", "")),
}).encode()
req = urllib.request.Request(url, body, {"Content-Type": "application/json"})
try:
    urllib.request.urlopen(req, timeout=5)
except Exception as e:
    print(f"webhook failed: {e}", file=sys.stderr)  # never fail the session
sys.exit(0)
{
  "hooks": {
    "Notification": [
      {"hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/webhook.py"}
      ]}
    ]
  }
}
$ echo '{"session_id":"s1","cwd":"$PWD","hook_event_name":"Notification","message":"Claude needs your permission to use Bash","title":"Permission needed","notification_type":"permission_prompt"}' | python3 webhook.py; echo "exit=$?"   # variable unset
exit=0
$ echo '{"session_id":"s1","cwd":"$PWD","hook_event_name":"Notification","message":"Claude needs your permission to use Bash","title":"Permission needed","notification_type":"permission_prompt"}' | CLAUDE_NOTIFY_WEBHOOK=http://127.0.0.1:8765/hook python3 webhook.py; echo "exit=$?"
exit=0
# the local test server received:
POST {"text": "Claude needs your permission to use Bash", "type": "permission_prompt", "project": "proj"}
$ echo '{"session_id":"s1","cwd":"$PWD","hook_event_name":"Notification","message":"Claude needs your permission to use Bash","title":"Permission needed","notification_type":"permission_prompt"}' | CLAUDE_NOTIFY_WEBHOOK=http://127.0.0.1:1/hook python3 webhook.py; echo "exit=$?"
webhook failed: <urlopen error [Errno 111] Connection refused>
exit=0

Tested against a throwaway server on localhost, not a real service.

Use several together

Put several entries in the same Notification array, or several matcher groups: for example the log on every type plus the desktop alert only on permission_prompt. Hooks that match run in parallel.

Before you trust a hook

Test each one by hand like above, then run the free hook_doctor.py on your settings file to catch missing scripts and relative paths. A webhook hook sends data out of your machine, so it is worth auditing: the agent-hook-audit tool is free, and the agent-config-audit Apify actor checks your whole setup at once.
