How to check a Claude Code skill before you install it

A skill is a SKILL.md file of instructions, often with scripts next to it. Claude follows those instructions and runs those scripts with your permissions. Most skills are fine. Here are four checks that take two minutes and catch the ones that aren't.

Clone or unpack the skill (or the plugin that ships it) into a folder and run each check from inside that folder. None of them runs code from the skill.

1. Hidden characters

Zero-width spaces, bidirectional overrides and Unicode tag characters are invisible in most editors and on GitHub, but the model reads them. They are the classic way to hide an instruction in plain sight. A normal skill has none:

python3 - <<'EOF'
import pathlib, unicodedata
for p in pathlib.Path(".").rglob("*.md"):
    for n, line in enumerate(p.read_text(errors="replace").splitlines(), 1):
        bad = [f"U+{ord(c):04X}" for c in line if unicodedata.category(c) == "Cf"]
        if bad: print(f"{p}:{n}: hidden characters {' '.join(bad)}")
EOF
evil-skill/SKILL.md:6: hidden characters U+200B

Any output is worth reading closely. Emoji sequences can contain U+200D legitimately; anything else in an instruction file is a red flag.

2. Instructions aimed at the agent, not at the task

grep -rniE 'ignore (all )?(previous|prior) instructions|do not (tell|inform) the user|without (telling|asking) the user' --include='*.md' .

A formatting skill has no reason to tell Claude to keep secrets from you. Also skim the whole SKILL.md: it is usually short, and reading it is the best check there is.

3. How much shell access it asks for

The allowed-tools line in the frontmatter lets a skill use tools without asking you each time. Bash on its own means any command:

grep -rnE '^allowed-tools:.*\bBash\b([^(]|$)' --include=SKILL.md .

A scoped grant like Bash(git diff:*) does not match. If a skill needs broad shell access, that's a reason to read its scripts first.

4. Scripts that read your keys and can reach the network

Using the network or reading config is normal on its own. Doing both in one script is how credentials leave a machine:

grep -rlE 'urllib|requests|httpx|socket|curl|wget|fetch\(' . \
  | xargs grep -lE '\.ssh|\.aws|\.env|id_rsa|_TOKEN|API_KEY'

Every file this prints needs a line-by-line read before you install.

Don't forget hooks

Plugins can also add hooks, shell commands that run on every tool call and keep running after you stop using the skill. How to audit Claude Code hooks covers that in 10 seconds, and a guard hook stops the worst commands even if something slips through.

What these checks don't do

They find known patterns. An obfuscated script or a cleverly worded instruction can get past grep. Treat a clean result as "no red flags", keep version control, and try unfamiliar plugins in a container first.
