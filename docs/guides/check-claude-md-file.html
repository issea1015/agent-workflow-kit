Check your CLAUDE.md: length, broken @imports, pasted keys

CLAUDE.md is read into every Claude Code session. It grows one "remember this" at a time, until it's long, points at files that moved, says "always" in one place and "never" in another, and sometimes holds a token someone pasted in a hurry. Here's how to check it in one command.

What gets loaded

Claude Code reads CLAUDE.md memory files when a session starts: your user file ~/.claude/CLAUDE.md, the project's CLAUDE.md (or .claude/CLAUDE.md), and CLAUDE.md files in parent directories. A file can pull in another with an import line such as @docs/conventions.md; relative paths resolve from the file that contains the import, and imports inside code spans and code blocks are ignored. Type /memory inside Claude Code to see and edit the files in use.

Everything in those files costs context in every session, whether the task needs it or not.

Four things that go wrong

  • Too long. Hundreds of lines of rules dilute the few that matter and use up context. Keep the file to what applies to almost every task; move the rest into a separate file and import it, or link it.
  • Broken @imports. A renamed or deleted file means the import quietly brings in nothing.
  • Secrets. A token in CLAUDE.md is sent to the model every session, and if the file is committed, it's in your git history. Remove it and rotate the key.
  • Contradictions. "Always use pnpm" in the project file and "Never use pnpm" in CLAUDE.local.md leaves the agent guessing.

Check it in one command (free)

claude_md_check.py is a free, read-only Python script (standard library only; no network, no writes). With no arguments it checks CLAUDE.md, .claude/CLAUDE.md and CLAUDE.local.md in the current directory and its parents, plus ~/.claude/CLAUDE.md, and follows their @imports. Here it is on a sample project:

$ cat CLAUDE.md
# My app
- Always use pnpm.
- Never commit to main.
- Code style: @docs/conventions.md
- API reference: @docs/api.md
- Staging DB password = Tr0ub4dor-staging
- Deploy key: AKIAIOSFODNN7EXAMPLE

$ python3 claude_md_check.py CLAUDE.md CLAUDE.local.md
HIGH  CLAUDE.md:6: possible password or secret assignment (passwo...(28 chars)); remove it and rotate the key
HIGH  CLAUDE.md:7: possible AWS access key id (AKIAIO...(20 chars)); remove it and rotate the key
ERROR CLAUDE.md:5: @docs/api.md imports a file that does not exist (docs/api.md)
WARN  CLAUDE.md:2, CLAUDE.local.md:2: contradicting instructions: 'always use pnpm' and 'never use pnpm'
INFO  CLAUDE.md:3, CLAUDE.local.md:3: same instruction repeated 2 times: 'never commit to main'
checked 3 file(s), ~69 tokens: FAIL (3 high/error, 2 other)

Secrets are printed redacted. It also warns when a file is over 200 lines, when all memory together is over roughly 5,000 tokens, on import cycles, and on imports nested more than five deep. It exits with code 1 on any HIGH or ERROR, so you can run it in a pre-commit hook or CI.

The contradiction check is deliberately simple: it only pairs lines that start with "always" and "never" followed by the same words. It won't catch every conflict, but what it flags is real.

Keep keys out of the session, not just the file
