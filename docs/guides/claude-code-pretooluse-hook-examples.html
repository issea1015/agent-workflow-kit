Claude Code PreToolUse hook examples: 5 copy-paste hooks (tested)

A PreToolUse hook runs before Claude Code uses a tool and can stop the call. Here are five small hooks you can paste in today, each tested by piping in the same JSON Claude Code sends.

How a PreToolUse hook works

Claude Code sends the hook a JSON object on stdin with tool_name and tool_input (for Bash, tool_input.command; for Read, Edit and Write, tool_input.file_path). The exit code decides:

  • exit 0: allow the call.
  • exit 2: block it. stderr is shown to Claude as the reason, so Claude can try another way.
  • any other code: reported as a hook error, and the call is not blocked.

Save the scripts in .claude/hooks/ and register them in .claude/settings.json. This file wires up examples 2–5:

{
  "hooks": {
    "PreToolUse": [
      {"matcher": "Bash", "hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/no_push_main.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/log_bash.py"}
      ]},
      {"matcher": "Read|Edit|Write", "hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect_env.py"}
      ]},
      {"matcher": "Edit|Write", "hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/stay_in_project.py"}
      ]}
    ]
  }
}

1. Block rm -rf and other destructive commands

Don't write this one from scratch: a regex for rm -rf misses rm -r -f, rm --recursive, find -delete and more. Use the free guard-dangerous-bash hook, which covers these and has tests. Details: how to stop Claude Code from running rm -rf.

2. Protect .env and key files

Stops Claude's file tools from reading or editing secrets. Matcher: Read|Edit|Write.

import json, sys, os
data = json.load(sys.stdin)
path = data.get("tool_input", {}).get("file_path", "")
name = os.path.basename(path)
if name == ".env" or name.startswith(".env.") or name.endswith((".pem", ".key")):
    print(f"Blocked: {name} holds secrets. Ask the user to edit it.", file=sys.stderr)
    sys.exit(2)
sys.exit(0)
$ echo '{"tool_name":"Edit","tool_input":{"file_path":"/repo/.env"}}' | python3 protect_env.py; echo "exit=$?"
Blocked: .env holds secrets. Ask the user to edit it.
exit=2

This covers the file tools only. cat .env through Bash is a separate path; deny it in your permission rules too.

3. No pushes to main, no force pushes

Matcher: Bash. Pushing a feature branch still works.

import json, re, sys
cmd = json.load(sys.stdin).get("tool_input", {}).get("command", "")
if re.search(r"\bgit\s+push\b", cmd) and (re.search(r"\b(main|master)\b", cmd) or re.search(r"\s(-f|--force)\b", cmd)):
    print("Blocked: no pushes to main/master and no force pushes. Push a branch and open a PR.", file=sys.stderr)
    sys.exit(2)
sys.exit(0)
$ echo '{"tool_name":"Bash","tool_input":{"command":"git push origin main"}}' | python3 no_push_main.py; echo "exit=$?"
Blocked: no pushes to main/master and no force pushes. Push a branch and open a PR.
exit=2
$ echo '{"tool_name":"Bash","tool_input":{"command":"git push -u origin feat/login"}}' | python3 no_push_main.py; echo "exit=$?"
exit=0

A simple pattern check, not a sandbox: it stops the usual commands, not a determined workaround.

4. Log every Bash command

Matcher: Bash. Never blocks (always exit 0); appends a timestamped line to .claude/bash.log so you can review what ran.

import json, sys, datetime, os
data = json.load(sys.stdin)
cmd = data.get("tool_input", {}).get("command", "")
log = os.path.join(os.environ.get("CLAUDE_PROJECT_DIR", "."), ".claude", "bash.log")
os.makedirs(os.path.dirname(log), exist_ok=True)
with open(log, "a") as f:
    f.write(f"{datetime.datetime.now().isoformat(timespec='seconds')}\t{cmd}\n")
sys.exit(0)
$ cat .claude/bash.log
2026-11-14T13:17:04	npm test

5. Keep edits inside the project

Matcher: Edit|Write. Resolves symlinks and .. before comparing.

import json, os, sys
data = json.load(sys.stdin)
path = data.get("tool_input", {}).get("file_path", "")
root = os.path.realpath(os.environ.get("CLAUDE_PROJECT_DIR", os.getcwd()))
target = os.path.realpath(os.path.join(root, path))
if os.path.commonpath([root, target]) != root:
    print(f"Blocked: {path} is outside the project ({root}).", file=sys.stderr)
    sys.exit(2)
sys.exit(0)
$ echo '{"tool_name":"Write","tool_input":{"file_path":"../x.py"}}' | python3 stay_in_project.py; echo "exit=$?"
Blocked: ../x.py is outside the project (/home/me/proj).
exit=2

Before you trust a hook

A hook that crashes exits with 1, and exit 1 does not block. Test each hook by hand like above, then run the free hook_doctor.py on your settings file to catch wrong matcher case, missing scripts and relative paths:

$ python3 hook_doctor.py .claude/settings.json
checked 1 file(s): 0 error(s), 0 warning(s)
