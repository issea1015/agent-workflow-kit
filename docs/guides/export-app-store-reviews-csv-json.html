Export App Store reviews to CSV or JSON

Apple has no export button for reviews, but it does publish a free JSON feed of every app's recent reviews, one country at a time. Here is how to use it, where it stops, and how to scale it to many apps and countries.

1. Find the app id

Every App Store app has a numeric id. It is the number after id in the store URL: https://apps.apple.com/us/app/facebook/id284882215 is app 284882215. The iTunes Lookup API returns the app's metadata (name, developer, version, average rating, rating count) as JSON, with no key and no login:

https://itunes.apple.com/lookup?id=284882215&country=us

Look in results[0] for trackName, sellerName, version, averageUserRating, userRatingCount and releaseNotes. You can also pass several ids at once: ?id=284882215,310633997.

2. Read the customer-reviews feed

Apple publishes each app's reviews as a public RSS feed that can return JSON. One country, one page of up to 50 reviews:

https://itunes.apple.com/us/rss/customerreviews/page=1/id=284882215/sortby=mostrecent/json

Change us to any store country code (gb, de, jp, ...) and page= from 1 to 10. Each review is an object in feed.entry with the rating (im:rating), title, text (content), author name, app version (im:version), date (updated) and helpful votes (im:voteCount). Each value is wrapped as {"label": "..."}.

One quirk: on some pages the first entry describes the app itself instead of a review. It has no im:rating, so skip entries without one.

3. What the feed cannot do

  • Recent reviews only. 10 pages of 50 is about 500 reviews per app and per country, newest first. Older reviews are not exposed here. If you need history, collect on a schedule and keep what you collected.
  • One country at a time. There is no "all countries" feed. Reviews are per storefront, so you loop over country codes yourself.
  • Reviews only, no replies. Developer responses are not part of this feed.
  • Be gentle. There is no published rate limit for the feed, but the Lookup and Search APIs are documented at roughly 20 calls per minute. Pause between requests and retry on errors.
  • Reviews are public user content. Use them in line with applicable law and Apple's terms.

4. A working Python script (standard library only)

This fetches up to 10 pages for one app and one country and writes a CSV. It stops early when a page comes back empty or fails.

import csv, json, time, urllib.request

APP, COUNTRY = "284882215", "us"
URL = "https://itunes.apple.com/{c}/rss/customerreviews/page={p}/id={a}/sortby=mostrecent/json"

def label(node, *path):
    for k in path:
        node = (node or {}).get(k)
    return node.get("label") if isinstance(node, dict) else node

rows = []
for page in range(1, 11):
    try:
        with urllib.request.urlopen(URL.format(c=COUNTRY, p=page, a=APP), timeout=30) as r:
            feed = json.load(r)["feed"]
    except Exception:
        break                      # past the last page, or a transient error
    entries = feed.get("entry") or []
    if isinstance(entries, dict):  # a single entry comes back as an object
        entries = [entries]
    got = 0
    for e in entries:
        if label(e, "im:rating") is None:
            continue               # app description entry, not a review
        got += 1
        rows.append({
            "country": COUNTRY, "id": label(e, "id"),
            "rating": int(label(e, "im:rating")),
            "title": label(e, "title"), "text": label(e, "content"),
            "author": label(e, "author", "name"),
            "version": label(e, "im:version"), "date": label(e, "updated"),
            "votes": label(e, "im:voteCount"),
        })
    if got == 0:
        break
    time.sleep(1)

with open("reviews.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=list(rows[0]) if rows else ["id"])
    w.writeheader(); w.writerows(rows)
print(len(rows), "reviews")

5. Many apps and many countries

Wrap the loop in two more loops: for each app id, for each country code, fetch pages 1 to 10, and add appId to every row so one CSV holds everything. Two practical notes:

  • The cost is requests: 20 apps in 10 countries is 200 app-country pairs, up to 2,000 page requests. Sleep between calls and cache what you already fetched.
  • De-duplicate on the review id when you run it on a schedule, so each day's file only adds new reviews. Track the share of 1-2 star reviews per app version to notice a bad release early.
