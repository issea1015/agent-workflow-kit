Claude Code PostToolUse hook examples: 5 copy-paste hooks (tested)

A PostToolUse hook runs right after Claude Code finishes a tool call. It cannot undo the call, but it can clean up after it and tell Claude what went wrong. Five small hooks, each tested by piping in the JSON Claude Code sends.

How a PostToolUse hook works

The hook runs after the tool has already succeeded. Claude Code sends a JSON object on stdin with tool_name, tool_input (for Edit and Write, tool_input.file_path; for Bash, tool_input.command) and tool_response. The exit code decides what happens next:

  • exit 0: success, nothing shown to Claude.
  • exit 2: stderr is fed back to Claude so it can react. The tool call itself is not undone: the file is already written or the command already ran. Use PreToolUse if you need to stop a call (PreToolUse examples).
  • any other code: reported as a non-blocking hook error.

Save the scripts in .claude/hooks/ and register them in .claude/settings.json. This file wires up all five:

{
  "hooks": {
    "PostToolUse": [
      {"matcher": "Edit|Write", "hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/format_after_edit.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/lint_feedback.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/run_related_tests.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/secret_warning.py"}
      ]},
      {"matcher": "Bash", "hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/log_bash.py"}
      ]}
    ]
  }
}

Hooks that match the same event can run in parallel, so don't write hooks that depend on each other's order. Example 2 can lint the file before example 1 has formatted it; that is harmless here, but keep it in mind.

1. Auto-format a file after Claude edits it

Matcher: Edit|Write. Runs black, gofmt or prettier depending on the extension. If the formatter isn't installed (or the file type is unknown) it does nothing and exits 0, so it never breaks your session.

import json, os, shutil, subprocess, sys
data = json.load(sys.stdin)
path = data.get("tool_input", {}).get("file_path", "")
ext = os.path.splitext(path)[1]
cmds = {
    ".py": ["black", "-q"],
    ".go": ["gofmt", "-w"],
    ".js": ["prettier", "--write", "--log-level", "silent"],
    ".ts": ["prettier", "--write", "--log-level", "silent"],
    ".json": ["prettier", "--write", "--log-level", "silent"],
}
cmd = cmds.get(ext)
if cmd and os.path.isfile(path) and shutil.which(cmd[0]):
    subprocess.run(cmd + [path], capture_output=True)
sys.exit(0)  # formatter missing or unknown file type: do nothing
$ printf 'import os\nx=1\n' > a.py
$ echo '{"tool_name":"Edit","tool_input":{"file_path":"a.py"},"tool_response":{}}' | python3 format_after_edit.py; echo "exit=$?"
exit=0
$ cat a.py
import os

x = 1

Tested with black, gofmt and prettier installed; with a missing file or missing formatter it also exits 0.

2. Feed lint errors back to Claude

Matcher: Edit|Write. Runs ruff on Python files; if it finds problems, the report goes to stderr with exit 2 so Claude sees it and fixes the file. No ruff installed means it silently passes.

import json, os, shutil, subprocess, sys
data = json.load(sys.stdin)
path = data.get("tool_input", {}).get("file_path", "")
if path.endswith(".py") and os.path.isfile(path) and shutil.which("ruff"):
    r = subprocess.run(["ruff", "check", "--output-format=concise", path],
                       capture_output=True, text=True)
    if r.returncode != 0:
        print(f"ruff found problems in {path}:\n{r.stdout.strip()}", file=sys.stderr)
        sys.exit(2)
sys.exit(0)
$ echo '{"tool_name":"Write","tool_input":{"file_path":"a.py"},"tool_response":{}}' | python3 lint_feedback.py; echo "exit=$?"
ruff found problems in a.py:
a.py:1:1: I001 [*] Import block is un-sorted or un-formatted
a.py:1:8: F401 [*] `os` imported but unused
Found 2 errors.
[*] 2 fixable with the `--fix` option.
exit=2

3. Run the related tests after an edit

Matcher: Edit|Write. For m.py it runs test_m.py next to it, if that file exists. A failing test goes back to Claude via exit 2. Adapt the naming convention to your project.

import json, os, shutil, subprocess, sys
data = json.load(sys.stdin)
path = data.get("tool_input", {}).get("file_path", "")
base = os.path.basename(path)
if path.endswith(".py") and not base.startswith("test_") and shutil.which("pytest"):
    test = os.path.join(os.path.dirname(path) or ".", "test_" + base)
    if os.path.isfile(test):
        r = subprocess.run(["pytest", "-x", "-q", test], capture_output=True, text=True)
        if r.returncode != 0:
            print(f"Tests in {test} fail after your edit:\n{r.stdout[-1500:]}", file=sys.stderr)
            sys.exit(2)
sys.exit(0)
$ echo '{"tool_name":"Edit","tool_input":{"file_path":"m.py"},"tool_response":{}}' | python3 run_related_tests.py; echo "exit=$?"
Tests in ./test_m.py fail after your edit:
...
E       assert 1 == 2
FAILED test_m.py::test_f - assert 1 == 2
exit=2

Keep this to fast tests: the hook blocks until pytest finishes.

4. Log every Bash command

Matcher: Bash. Never reports anything (always exit 0); appends a timestamped line to .claude/bash-after.log. Because it runs after the call, it only records commands that actually ran, unlike a PreToolUse logger which also records ones that get blocked.

import json, sys, datetime, os
data = json.load(sys.stdin)
cmd = data.get("tool_input", {}).get("command", "")
log = os.path.join(os.environ.get("CLAUDE_PROJECT_DIR", "."), ".claude", "bash-after.log")
os.makedirs(os.path.dirname(log), exist_ok=True)
with open(log, "a") as f:
    f.write(f"{datetime.datetime.now().isoformat(timespec='seconds')}\t{json.dumps(cmd)}\n")
sys.exit(0)
$ echo '{"tool_name":"Bash","tool_input":{"command":"npm test"},"tool_response":{}}' | CLAUDE_PROJECT_DIR=$PWD python3 log_bash.py; echo "exit=$?"
exit=0
$ cat .claude/bash-after.log
2026-11-14T14:17:47	"npm test"

5. Flag a secret that was just written

Matcher: Edit|Write. Scans the written text (content for Write, new_string for Edit) for AWS keys, GitHub tokens, sk- style keys and private-key headers. The file is already saved, so this is an after-the-fact alarm: Claude is told to remove it and the user to rotate it.

import json, re, sys
ti = json.load(sys.stdin).get("tool_input", {})
text = ti.get("content") or ti.get("new_string") or ""
patterns = [r"AKIA[0-9A-Z]{16}", r"gh[pousr]_[A-Za-z0-9]{36,}", r"sk-[A-Za-z0-9_-]{20,}",
            r"-----BEGIN [A-Z ]*PRIVATE KEY-----"]
if any(re.search(p, text) for p in patterns):
    print(f"A secret-like string was just written to {ti.get('file_path','?')}. "
          "Remove it, load it from an environment variable instead, and tell the user to rotate it.",
          file=sys.stderr)
    sys.exit(2)
sys.exit(0)
$ echo '{"tool_name":"Write","tool_input":{"file_path":"cfg.py","content":"KEY=\"AKIAABCDEFGHIJKLMNOP\""},"tool_response":{}}' | python3 secret_warning.py; echo "exit=$?"
A secret-like string was just written to cfg.py. Remove it, load it from an environment variable instead, and tell the user to rotate it.
exit=2

A short pattern list, not a secret scanner. To stop secrets before they are written, block .env and key files with a PreToolUse hook.

Before you trust a hook

A hook that crashes exits with 1, which does not signal Claude. Test each one by hand like above, then run the free hook_doctor.py on your settings file to catch wrong matcher case, missing scripts and relative paths. If a hook still doesn't fire, see the 7-step checklist.
