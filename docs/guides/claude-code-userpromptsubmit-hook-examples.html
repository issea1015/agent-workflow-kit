Claude Code UserPromptSubmit hook examples: 5 copy-paste hooks (tested)

A UserPromptSubmit hook runs when you press Enter, before Claude sees your prompt. It can block the prompt or quietly add context to it. Five small hooks, each tested by piping in the JSON Claude Code sends.

How a UserPromptSubmit hook works

Claude Code sends a JSON object on stdin with prompt (the text you typed), session_id, cwd and hook_event_name. UserPromptSubmit takes no matcher: every hook in the group runs on every prompt. The exit code decides what happens:

  • exit 0: the prompt goes through. Anything the hook prints to stdout is added to the prompt as extra context for Claude.
  • exit 2: the prompt is blocked and erased. stderr is shown to you, not to Claude.
  • any other code: a non-blocking hook error; the prompt still goes through.

Instead of plain stdout, a hook can print JSON: {"decision": "block", "reason": "..."} to block, or hookSpecificOutput.additionalContext to add context (example 5). Save the scripts in .claude/hooks/ and register them in .claude/settings.json:

{
  "hooks": {
    "UserPromptSubmit": [
      {"hooks": [
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block_secrets.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/git_context.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/add_date.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/log_prompts.py"},
        {"type": "command", "command": "python3 \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/rules_reminder.py"}
      ]}
    ]
  }
}

Everything these hooks print becomes part of every prompt, so keep the output to one short line. Long context on each prompt costs tokens and distracts the model.

1. Block a prompt that contains an API key

People paste keys into prompts by accident. This hook checks for AWS keys, GitHub tokens, sk- style keys and private-key headers and stops the prompt before it is sent anywhere.

import json, re, sys
prompt = json.load(sys.stdin).get("prompt", "")
patterns = [r"AKIA[0-9A-Z]{16}", r"gh[pousr]_[A-Za-z0-9]{36,}", r"sk-[A-Za-z0-9_-]{20,}",
            r"-----BEGIN [A-Z ]*PRIVATE KEY-----"]
if any(re.search(p, prompt) for p in patterns):
    print("Prompt blocked: it contains what looks like an API key or private key. "
          "Remove it and reference an environment variable instead.", file=sys.stderr)
    sys.exit(2)
sys.exit(0)
$ echo '{"prompt":"use key sk-abcdefghijklmnopqrstuvwx to call the API"}' | python3 block_secrets.py; echo "exit=$?"
Prompt blocked: it contains what looks like an API key or private key. Remove it and reference an environment variable instead.
exit=2
$ echo '{"prompt":"fix the login test"}' | python3 block_secrets.py; echo "exit=$?"
exit=0

A short pattern list, not a full secret scanner. To catch secrets that Claude writes into files, see the PostToolUse examples.

2. Tell Claude which git branch you are on

Adds one line with the current branch and the number of uncommitted files, so Claude doesn't have to run git status to find out. Outside a git repo it adds nothing.

import json, subprocess, sys
cwd = json.load(sys.stdin).get("cwd") or "."
def git(*args):
    r = subprocess.run(["git", *args], cwd=cwd, capture_output=True, text=True)
    return r.stdout.strip() if r.returncode == 0 else ""
branch = git("branch", "--show-current")
if branch:
    changed = git("status", "--porcelain").splitlines()
    print(f"[context] git branch: {branch}; uncommitted files: {len(changed)}")
sys.exit(0)  # not a git repo: add nothing
$ echo '{"cwd":"'$PWD'","prompt":"fix the login test"}' | python3 git_context.py; echo "exit=$?"
[context] git branch: feature/login; uncommitted files: 1
exit=0
$ echo '{"cwd":"/tmp","prompt":"hi"}' | python3 git_context.py; echo "exit=$?"
exit=0

3. Add today's date and time

The model does not know what day it is. One line of context makes "what is due this week" or "add a changelog entry for today" come out right.

import datetime, json, sys
json.load(sys.stdin)
now = datetime.datetime.now().astimezone()
print(f"[context] current local time: {now.strftime('%Y-%m-%d %H:%M %Z')}")
sys.exit(0)
$ echo '{"prompt":"what is due this week?"}' | python3 add_date.py; echo "exit=$?"
[context] current local time: 2026-11-14 15:16 UTC
exit=0

4. Log every prompt

Appends each prompt with a timestamp and session id to .claude/prompts.log. Useful for reviewing what you asked for later, or for a team audit trail. Add the log to .gitignore.

import datetime, json, os, sys
data = json.load(sys.stdin)
log = os.path.join(os.environ.get("CLAUDE_PROJECT_DIR", "."), ".claude", "prompts.log")
os.makedirs(os.path.dirname(log), exist_ok=True)
with open(log, "a") as f:
    f.write(f"{datetime.datetime.now().isoformat(timespec='seconds')}\t"
            f"{data.get('session_id', '?')}\t{json.dumps(data.get('prompt', ''))}\n")
sys.exit(0)
$ echo '{"session_id":"abc123","prompt":"fix the login test"}' | CLAUDE_PROJECT_DIR=$PWD python3 log_prompts.py; echo "exit=$?"
exit=0
$ cat .claude/prompts.log
2026-11-14T15:16:11	abc123	"fix the login test"

5. Remind Claude of project rules on keywords

Instead of putting every rule in CLAUDE.md, inject a rule only when the prompt mentions the topic. This one uses the JSON output form with additionalContext; edit the rules map for your project.

import json, re, sys
prompt = json.load(sys.stdin).get("prompt", "").lower()
rules = {
    r"\b(deploy|release|publish)\b": "Before deploying: run the full test suite and never push to main directly.",
    r"\b(migration|migrate|schema)\b": "Database changes need a reversible migration file in db/migrations/.",
}
hits = [msg for pat, msg in rules.items() if re.search(pat, prompt)]
if hits:
    print(json.dumps({"hookSpecificOutput": {"hookEventName": "UserPromptSubmit",
                                             "additionalContext": " ".join(hits)}}))
sys.exit(0)
$ echo '{"prompt":"Deploy the new schema"}' | python3 rules_reminder.py; echo "exit=$?"
{"hookSpecificOutput": {"hookEventName": "UserPromptSubmit", "additionalContext": "Before deploying: run the full test suite and never push to main directly. Database changes need a reversible migration file in db/migrations/."}}
exit=0
$ echo '{"prompt":"rename this variable"}' | python3 rules_reminder.py; echo "exit=$?"
exit=0

Before you trust a hook

A hook that crashes exits with 1, which does not block anything. Test each one by hand like above, then run the free hook_doctor.py on your settings file to catch missing scripts and relative paths. If a hook still doesn't fire, see the 7-step checklist.
